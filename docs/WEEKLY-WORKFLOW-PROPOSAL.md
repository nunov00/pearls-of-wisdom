Do not manufacture reviews on unchanged ready content. Sunday topic/ranking prerequisites cannot move to an article slot. Within Monday–Thursday's existing dated opportunities, a missed article delivery can be resumed with the next unused review number and a new explicit Manager attempt for today's slotDate, never an extra session or replay of a past dated slot. Genuine Paused results consume their number and may be repaired in the next opportunity. Actual date routing, current-main policy, observed review history and dependencies all apply. Setup must be verified and enabled before the first Sunday morning slot. Report unexposed notification/session settings; no task summary alone proves provider execution.

## Quality and terminal disposition

Publish only with author AND Claude whole-article scores >=9/10 on the same exact final article/illustration bytes, all actual evidence/QA and passing checks, and no unresolved blocker/important findings. No averaging, rounding, score inflation or false claim of source/render access. A ready pair freezes the content early and remaining slots no-op after verifying unchanged inputs. Any changed advice, wording or illustration needs renewed review within the remaining budget. Friday is record-only integration/release verification, not unreviewed final editing.

If review 4 remains below either score or has blocking/important findings, return the article to backlog with reasons and remaining work. Missing/Paused reviews or failed verification at Friday's decision also mean Backlog, no release record/publication. The Manager performs and records this manual Friday disposition, even if there is no publication. Recommissioning backlog content is a separate recorded decision preserving its unresolved history; no fifth automatic review or budget reset. Both scores are a manual editorial release condition, not an automated score schema.

## Exact inputs, duplicate protection and drift

Each Manager-issued stage request names runId, stage, reviewNumber (0 for topic; 1–4 for article), correctionRounds (0–3), attempt, input and prerequisite evidence in the tracking issue. For topic, prefer the brief file at its full Git commit SHA. If using a GitHub comment, input is comment ID plus SHA-256 of the UTF-8 encoding of the body field exactly as returned by the GitHub REST API, with no line-ending normalisation, trimming or Markdown conversion; both Manager and reviewer fetch and hash that returned field rather than local submitted text. A comment ID alone is not immutable. Read and verify that body hash at the start and end; author ratings are in a separate comment, opened only after initial judgement. For article, input is the full PR head SHA plus article path. The Manager assigns attempt 1 initially and increments it only after explicitly reconciling a pause or drift and recording changed prerequisites.

If no Manager-issued request exists for this task's stage, post nothing on GitHub; report the missing request to the Owner in the task's run summary/notification. Do not invent an attempt or act on an older cycle.

For the scheduled task's run, stage, current slotDate and actual next unused reviewNumber, select the highest-numbered Manager-issued attempt. Act only if it has no Claude comment with that exact key. If it already has a comment, stop; never fall back to an older unanswered attempt or resurrect a superseded input. Duplicate/ambiguous requests pause without GitHub posting and report the blocker in the run summary.

Each Claude review comment begins:
`Claude <topic|article> review · run <runId> · slot <actual Zurich date> · review <0|1|2|3|4> · input <immutable input> · attempt <N>`

Before reviewing, search all issue and PR comments for that exact key. If one exists, stop without reposting, including if its outcome was Paused. A later permitted retry needs a new Manager-issued attempt. A new head is a new input. This prevents duplicate comments while allowing a recovered run to use a new attempt. It does not cause that replacement attempt to execute.

Missing prerequisites produce Paused, not a passing assessment. Reviews do not edit the tracking summary. The Manager reconciles a lost-comment response before authorising another attempt.

Manager-side writes re-read expected head and stage first; use guarded updates where supported. ## Publication date, hashes and final integration

Monday sets the new article's intended publishedAt to the target Friday before article review 1. Sunday–Thursday independent reviews may verify that intended future date in editorial preview; no publication is claimed. A future draft date is permissible in the article schema; do not add a future-dated publication record or attempt a release build selecting it before that date. Use the editorial preview for layout. Existing articles' original dates remain unchanged.

Article reviewers hash the exact article file bytes at the reviewed immutable commit and record the full commit and SHA-256. They also resolve every referenced illustration (overview images and any figure), record its repository path and SHA-256 of the raw file bytes, and flag missing or unresolved assets. Map article site paths such as /figures/x.webp to repository paths public/figures/x.webp and record repository paths consistently. Reject unresolved or ambiguous mappings. Deduplicate repeated paths. Include article-specific images referenced by shared components when they appear on this article page. Generic shared chrome assets are outside this article illustration manifest; freeze them during the content PR, inspect the full diff and flag any shared component/asset changes for separate review rather than silently treating them as record-only. This asset manifest supplements articleSha256; it does not change the release-record schema. The Manager copies the actual review identity, decision, hash, commit, correction count and findings into the release records; it never creates a review it did not receive.

A later record-only commit changes the PR head. Before merging, the manual Manager performs and records final integration review of that actual head: mechanically compare article bytes/hash and every referenced image path/hash against the reviewer manifest, inspect the record-only diff and base changes, and require green checks plus the release build. This integration check is not falsely attributed to Claude. Any substantive article/asset change goes back to the separate reviewer.

On Friday, publishedAt must equal the intended actual first-release date, match publication records, and not be in the future. If release slips to another calendar day, update the first-release date and obtain renewed separate review and hash validation before release. No implicit date-only waiver or backdating. Preserve dates of already published articles on revision.
