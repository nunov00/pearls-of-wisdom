# Monday release evidence and cycle records

This contract is for implementation and review. It does not activate publishing or replace the existing manual release policy.

Use one scheduled Codex task for all seven weekly dispatches from the [Monday design](weekly-production-design.md). Claude uses one separate reviewer routine. The Tuesday watchdog runs in GitHub Actions.

## Cycle ledger

Use one GitHub issue, with append-only comments, for activation and cycle evidence. Derive the slot from actual Zurich dispatch time with `weeklySlot` and use `weeklyReservationKey(slot)` as the stage key. Before any editorial write or generation, read the ledger and reconcile the candidate PR and current Git state. Append a start entry with the unique run ID and reread it. Stop before mutation if another start exists for the key, a prior stage is incomplete, or the read or write is uncertain. Recheck before writes and generation. This is procedural duplicate handling, as in Five Minutes. Issue comments do not provide an atomic lock. Do not run overlapping jobs for the same stage, replay uncertain mutations, or use the experimental Git ref adapter. A later run may append an abandoned outcome for an orphaned start only after checking the PR, Git and image-generation history and verifying that no mutation occurred. Otherwise mark the cycle Blocked. Abandonment does not reopen a missed slot. Claude's routine appends its own review-stage start and only writes review evidence for a recorded request. It does not edit or publish the candidate.

Keep one candidate and one terminal outcome per Tuesday cycle. Record Published only after checking the live site. Otherwise record Deferred or Blocked, or leave deployment pending until reconciled. The Tuesday GitHub Actions watchdog reads the same ledger. There is one scheduled Codex task and one separate Claude review routine.

## Release through the existing Cloudflare build

Keep the current publication and review JSON files and Cloudflare's existing build from `main`. Set the article YAML's `publishedAt` to the intended Monday before its first editorial review. A deferred article needs a new date and fresh review in a later authorised cycle. Use the cycle ledger for the intent and exact-head receipts. Require separate Codex and Claude scores of at least 9/10 for the article and cover, both linked to the reviewed article commit and exact article and image hashes. The trusted check reads the designated GitHub ledger issue and requires unedited receipt comments from the authorised GitHub account, distinct provider run or session references, and a match to the recorded request, content commit and all three hashes. It also checks Claude's approval line for the final integration head. Missing, edited or inconsistent evidence blocks. This is procedural provenance at the same trust level as `Governance verdict`. The shared GitHub account cannot independently authenticate which provider authored a comment.

Once both editorial receipts qualify, prepare the standard publication and review records from the completed evidence on the same PR before Monday. The review record names the actual earlier article commit. The next existing Claude slot may independently approve the final integration head after confirming that the only post-review changes are the matching release records and that all reviewed bytes are identical. The technical approval uses an existing Claude dispatch window and does not count as an editorial review or add a dispatch. It cannot revise or rescore the article or change its date. A candidate first qualifying on Saturday must defer because there is no remaining slot for the record-only handoff. Monday dispatches a fresh check from trusted `main` immediately before merging and requires success from that specific run on the current head and base. An older green verdict cannot stand in for a failed, cancelled or missing run. If `main` moves after editorial review and the record-only rule cannot be met, defer. Monday verifies the unchanged approved head, the receipt and record correspondence, green required checks and the actual Zurich date, then merges and verifies the existing Cloudflare deployment.

Identify a weekly PR by its canonical ledger entry binding PR number, cycle and candidate. A weekly branch prefix also triggers the weekly check so missing ledger evidence cannot fall through. Non-release PRs pass this check. Publication or review record changes must qualify under the weekly or existing manual release policy. Unclassified changes fail closed. Add the check to the existing Protect main ruleset after live verification. The dedicated release check must use trusted base code and reject missing evidence, changes outside the allowed paths, inconsistent records and any drift in the reviewed article or images. The editorial content SHA and the approved final PR head serve distinct purposes. Before activation, independently review and test this distinction, simulate overlapping or uncertain dispatches and verify that the existing release build still includes older articles. The implementation must remove or retire the Git ref adapter and unused in-memory projection. This design has no runtime authority.
